# 캐릭터 만들기 공방 (AI 캐릭터 메이커 MVP)

이름/반 선택 → 가이드 따라 그리기 → 채색 → 캐릭터 시트 → 제출까지 진행하는 초등학생용 교육용 웹앱입니다.
바닐라 HTML/CSS/JS로 만들어져 있어 Stickman Class와 동일하게 GitHub Pages에 그대로 올릴 수 있어요.

## 파일 구성
- `index.html` – 전체 화면 구조 (4단계 스텝)
- `style.css` – 크레용/스케치북 테마 스타일
- `app.js` – 캔버스 드로잉, 채색(채우기+선 잇기), 캐릭터 시트, 제출 로직
- `config.js` – 가이드 이미지 목록, Cloudinary 제출 연동 설정 (⚠️ .gitignore에 포함됨)
- `guides/` – STEP 1에서 반투명하게 비춰줄 가이드 밑그림들 (여우, 코끼리, 펭귄, 고양이, 곰, 다람쥐 기본 포함)

## 로컬에서 열어보기
```bash
cd character-maker
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```
`file://`로 직접 열어도 대부분 동작하지만, 일부 브라우저는 이미지 로드를 막을 수 있어 로컬 서버 실행을 권장해요.

## 시작 화면 — 이름/반 선택 → 수업 시작하기
앱을 열면 바로 STEP 1로 들어가지 않고, 이름과 반을 입력하는 시작 화면이 먼저 나옵니다 (Stickman Class의 index.html 구조를 참고했습니다).
- 반 목록은 Stickman Class와 동일한 8개 학급(신남초 돌봄A/B, 신도림초 A/B, 등현초A/B, 신남초 A/B)이 기본으로 들어있어요. `index.html`의 `#studentClassSelect` 안 `<option>`을 수정하면 목록을 바꿀 수 있습니다.
- 이름과 반 **둘 다 선택해야** 시작할 수 있습니다. 비어있으면 alert 대신 화면 하단에 잠깐 뜨는 토스트 알림으로 안내해요 (Stickman Class와 같은 방식).
- 이름은 STEP 3 캐릭터 시트의 "작가 이름" 칸에 자동으로 채워집니다.
- 반 이름은 STEP 4 제출 시 Cloudinary 파일명 앞부분과 메타데이터에 함께 실립니다.
- **"수업 시작하기" 버튼을 누르는 순간 전체화면(키오스크) 모드로 진입합니다.** (앞으로 만드는 다른 앱들도 이름/반 선택 후 시작 버튼에서 전체화면 진입하는 이 패턴을 표준으로 쓰기로 하셨죠 — `classroom-input-guard.js`를 그대로 재사용하면 됩니다.)

## STEP 1 — 가이드 따라 그리기
자유 스케치가 아니라, 캐릭터를 하나 골라서 반투명한 가이드 밑그림 위에 따라 그리는 방식입니다.
- `config.js`의 `GUIDE_IMAGES` 배열에 등록된 캐릭터들이 캔버스 위에 이미지 썸네일로만 나옵니다 (글자 라벨 없음). 지금은 여우/코끼리/펭귄/고양이/곰/다람쥐 6종이 `guides/` 폴더에 들어있어요.
- 캐릭터를 바꾸면 지금까지 그린 선과 실행취소 기록이 함께 초기화됩니다.
- 파일을 못 찾으면 에러 없이 그냥 흰 캔버스로 진행됩니다 (앱이 멈추지 않아요).
- 가이드 진하기는 `config.js`의 `GUIDE_OPACITY` (0~1)로 조절하세요. 기본값 0.32.
- 캔버스 위 오른쪽에는 ➕/➖(확대·축소)와 ✋(팬/이동) 버튼이 동그란 아이콘으로 떠 있습니다 — 그리기 영역을 가리지 않도록, 버튼이 있는 자리만 클릭을 받고 나머지는 그대로 캔버스에 그려집니다.
- 캔버스 아래 도구 버튼은 아이콘만 큼직하게 표시됩니다: 🖊️(펜), 🧽(지우개), ↩️(실행취소), 🗑️(전체지우기), 👁️(가이드 숨기기/보기 토글).
- **PC 커서**: 브러시 굵기를 원으로 보여주던 방식은 모드에 따라 나타났다 사라졌다 해서 예측하기 어려웠던 문제가 있어, **단순한 십자(crosshair) 커서**로 통일했습니다. 채우기/펜 모드 상관없이 항상 같은 모양으로 보여서 더 예측 가능해요. 모바일(터치)에서는 애초에 마우스 커서 개념이 없어서 특별히 처리할 게 없습니다.
- **확대(줌) 상태에서 그리기 위치가 어긋나던 버그 수정**: 손떨림 방지 보정을 캔버스 내부 좌표계에서 계산하고 있었는데, 확대된 상태에서는 같은 마우스 이동량이라도 내부 좌표 변화가 작아져서 보정이 과하게 걸리고, 그 결과 커서 위치와 실제로 선이 그려지는 위치가 눈에 띄게 어긋나 보였습니다. 이제 보정 계산을 화면(스크린) 좌표계에서 먼저 수행한 뒤 캔버스 좌표로 변환하도록 고쳐서, 확대 배율과 관계없이 커서를 따라 정확한 위치에 그려집니다 (STEP 1, STEP 2 모두 적용).
- **지우개 버그 수정**: 이전에는 지우개가 흰색을 칠하는 방식이라 아래 비치는 가이드까지 하얗게 덮어버렸는데, 이제는 실제로 그 부분만 투명하게 지우는 방식(destination-out)으로 바꿔서 가이드가 항상 정상적으로 비쳐 보입니다.
- 가이드와 학생이 그린 선은 각각 다른 레이어(캔버스)에 그려져서, 다음 단계로 넘어갈 때는 가이드는 빼고 학생이 그린 선만 흰 배경 위에 합쳐서 전달합니다.

## STEP 2 — 채색 (채우기 + 펜)
별도의 "선 정리" 단계 없이 바로 채색으로 넘어옵니다. 캔버스 바로 아래에 줌/채우기/펜/실행취소/초기화 버튼이 한 줄로 모여있어요.

- **🪣 채우기 (기본 모드)**: 캔버스를 톡 누르면 Flood Fill로 그 영역이 색칠됩니다.
- **🖊️ 펜**: 끊어진 선 때문에 채우기를 눌렀을 때 색이 원치 않는 곳까지 새어나가면, 이 모드로 바꿔서 검정 펜으로 끊어진 부분을 직접 이어 그릴 수 있습니다. 펜 모드에서는 팔레트의 검정 스와치가 자동으로 선택된 것처럼 표시되고, 채우기 모드로 돌아가면 원래 고르셨던 색으로 하이라이트가 되돌아갑니다. 브러시 굵기 원형 커서도 함께 표시돼요.
- **↩️ 실행 취소 / 🗑️ 초기화**: 채우기·펜 두 모드 모두 같은 실행취소 기록(최근 15단계)을 공유합니다.
- **🔍➖/🔍➕/✋**: STEP 1과 같은 방식으로 캔버스 위 오른쪽에 떠 있는 확대·축소·팬(이동) 버튼입니다. ✋를 누르면 이동 모드가 되어 확대된 화면을 드래그해서 볼 수 있고, 이동 모드 중에는 채색/펜 동작이 잠깁니다.
- **🖊️ 펜 아이콘을 두 번 빠르게 누르면(더블탭) 줌이 원래 크기(100%)로 바로 돌아갑니다.** 별도의 돋보기(리셋) 버튼 없이도 빠르게 원래 크기로 되돌릴 수 있는 단축 동작이에요. STEP 1의 펜 도구 버튼에도 동일하게 적용됩니다.

팔레트는 기본 8색 + 밝은 스킨톤(피부색) + 마지막 **🌈 무지개 버튼**으로 구성됩니다. 별도의 "다른 색" 메뉴는 없고, 무지개 버튼을 누르면 브라우저 기본 색상 선택 창이 열려서 원하는 색을 직접 조합해 고를 수 있어요. PC에서는 버튼 바로 위쪽에 뜨도록 위치를 맞췄고, 숨김 처리 방식도 모바일에서 확실히 열리도록 `display:none` 대신 투명 처리 방식으로 바꿨습니다.

**"저장하고 다음"**을 누르면 그 시점의 라인아트·채색 이미지를 브라우저 `localStorage`에 임시 저장(`characterMakerDraft` 키)한 뒤 화면 하단에 저장 완료 토스트가 뜨고 STEP 3으로 이동합니다. 저장 직후 방금 쓴 값을 다시 읽어서 실제로 남아있는지 확인하는 검증 단계를 추가했습니다 — 일부 브라우저(시크릿 모드, 저장공간이 제한된 웹뷰 등)는 `localStorage.setItem()`이 에러 없이 넘어가는데도 실제로는 저장이 안 되는 경우가 있어서, 이 검증이 없으면 "저장됐다고 나오는데 실제로는 없는" 상황을 앱이 알아챌 수 없었습니다. 지금은 검증에 실패하면 "⚠️ 로컬 저장에 실패했어요"로 정확하게 안내됩니다.
⚠️ 참고: 시크릿/프라이빗 브라우징 모드는 브라우저를 완전히 닫으면 저장된 내용이 사라지는 게 정상 동작입니다 (이 앱만의 문제가 아니라 모든 웹사이트가 그래요). 확인은 같은 창을 유지한 채로 개발자도구 콘솔에서 `localStorage.getItem('characterMakerDraft')`로 해보시는 게 정확합니다.

## STEP 3 — 캐릭터 시트
- 성격/강점/약점은 이제 **드롭다운(select)**으로 고르고, 목록 맨 아래 "✏️ 직접입력"을 선택하면 텍스트 입력칸이 나타납니다.
- 말풍선은 손잡이(⠿, 커진 크기)를 드래그해서 위치를 옮기고, 텍스트 영역을 탭해서 글을 쓸 수 있습니다. 말풍선 글자 크기도 더 크게 키웠습니다 (화면 표시와 최종 제출 이미지 모두).

## STEP 4 — 제출
버튼 4개가 있습니다: **📮 제출하기**(주 버튼, 위에 크게), **← 이전으로**, **🆕 새 캐릭터 만들기**, **🎬 애니메이션 만들기**(아래에 작게, 한 줄로). 예전에는 버튼이 전부 커서 화면을 많이 차지했는데, 보조 버튼 3개는 작은 크기로 줄이고 한 줄에 나란히 배치했습니다.

- **← 이전으로**: STEP 3(캐릭터 시트)로 돌아갑니다.
- **🎬 애니메이션 만들기**: 새 탭으로 `https://sketch.metademolab.com/`을 엽니다.

`config.js`에 Cloudinary unsigned upload 정보(Stickman Class에서 쓰신 것과 동일한 방식)를 넣어주셔야 제출하기가 실제로 업로드까지 이어집니다.

⚠️ **지금 배포본은 `CLOUDINARY_CLOUD_NAME` / `CLOUDINARY_UPLOAD_PRESET`이 빈 값 그대로예요.** 이 상태에서 제출하기를 누르면 항상 "⚠️ 제출 기능이 아직 연결되지 않았어요" 메시지만 뜨고 실제 전송은 되지 않습니다 — 이건 버그가 아니라 아직 값이 채워지지 않아서예요. 실제 Cloudinary 클라우드 이름/업로드 프리셋 값을 넣어주시면 정상 작동합니다.

업로드되는 위치/파일명 규칙:
- 루트의 **`ch-maker`** 폴더 아래 저장됩니다.
- 파일명은 **`이름_반_캐릭터이름_시간.png`** 형식입니다 (예: `홍길동_신남초A_불꽃여우_1737890123456.png`).
- ⚠️ Cloudinary 콘솔의 unsigned upload preset 설정에서 "Use filename or externally defined Public ID"와 폴더 지정 허용이 켜져 있어야 이 folder/파일명 규칙이 실제로 적용됩니다. (Stickman Class에서 이미 폴더별 업로드를 쓰고 계시니 같은 프리셋을 쓰신다면 대부분 이미 허용되어 있을 거예요.)

**제출하기 기능 점검 및 수정 내역:**
- STEP 3에서 "완성하러 가기"를 누르면 최종 이미지(캐릭터+말풍선+글자)를 캔버스에 그리는 작업이 비동기로 진행되는데, 이전에는 이 작업이 끝나기 전에 "제출하기"를 빠르게 누르면 배경만 그려진 빈 이미지가 제출될 수 있는 레이스컨디션이 있었습니다 → **이제 그림이 준비되는 동안 제출 버튼이 비활성화**되고, "🖼️ 그림을 준비하는 중이에요..." 안내가 뜹니다. 혹시 그 사이에 눌러도 내부적으로 준비가 끝날 때까지 기다린 뒤 제출하도록 고쳤습니다.
- 제출 중 중복 클릭으로 같은 그림이 두 번 올라가는 것을 막기 위해, 제출 진행 중에는 버튼이 비활성화되고 **성공하면 다시 누를 필요 없도록 계속 비활성 상태**로 남습니다. 실패하면 버튼이 다시 활성화되어 재시도할 수 있습니다.
- Cloudinary 업로드 실패 시 콘솔에 응답 상태 코드와 본문 일부를 함께 남기도록 해서, 실제 배포 후 문제가 생기면 브라우저 개발자도구로 원인을 더 쉽게 확인할 수 있습니다.

**"🆕 새 캐릭터 만들기"**를 누르면 이름/반 선택 화면으로 돌아가지 않고, 같은 학생이 바로 STEP 1(가이드 따라 그리기)부터 다시 시작합니다. 전체화면 상태와 이름/반 정보는 그대로 유지되고, 그림·채색·캐릭터 시트·임시저장 데이터·제출 버튼 상태까지 모두 초기화됩니다.

## 전체화면 유지를 위한 커스텀 확인창
`window.confirm()`/`alert()`은 호출되는 순간 브라우저가 전체화면을 강제로 풀어버리는 경우가 많아서, "새 캐릭터 만들기", "처음부터 다시", "초기화" 같은 확인이 필요한 동작은 전부 페이지 안의 커스텀 모달(`showConfirmModal()`)로 바꿨습니다. 덕분에 이 버튼들을 눌러도 전체화면이 풀리지 않습니다.

## 줌 + 팬(이동) 동작 원리
캔버스를 CSS로 확대(`width: %`)하고, 뷰포트(`overflow:auto`)를 통해 스크롤 가능하게 만드는 방식입니다. 그림을 그리는 캔버스에는 `touch-action:none`이 걸려있어 네이티브 터치 스크롤이 동작하지 않기 때문에, ✋ 팬 모드에서는 JS로 직접 `scrollLeft`/`scrollTop`을 옮겨서 이동을 구현했습니다. 팬 모드가 켜져 있는 동안은 펜/지우개/채우기 등 그리기 동작이 잠깁니다.

## 여러 앱 공용: classroom-input-guard.js
이 파일은 이 프로젝트뿐 아니라 Stickman Class, 웹툰 메이커 등 다른 그림 수업 앱에도 그대로 복사해서 쓸 수 있는 **독립적인 유틸리티**입니다. 다른 앱에서는 `<script src="classroom-input-guard.js"></script>`를 `app.js`(또는 해당 앱의 메인 스크립트)보다 먼저 한 줄 추가하기만 하면 됩니다. 의존성 없는 순수 JS라 그대로 복사해도 됩니다.

**1) 전체화면(키오스크) 모드** — 뒤로가기/바탕화면이 실수로 보이지 않도록 앱을 전체화면으로 실행합니다.

표준 패턴(이 프로젝트에서 쓰는 방식): 앱 로드 시 나가기 제스처만 미리 켜두고, 실제 진입은 "이름/반 선택 → 수업 시작하기" 버튼 클릭 안에서 호출합니다.
```js
// 앱 로드 시 (DOMContentLoaded 등) - 나가기 제스처(ESC/구석탭)만 활성화, 자동 진입은 끔
ClassroomGuard.fullscreen.enable({ autoRequestOnFirstGesture: false });

// "수업 시작하기" 버튼의 click 핸들러 안에서
document.getElementById('btn-start-class').addEventListener('click', () => {
  ClassroomGuard.fullscreen.request().catch(() => {});
  // ...이후 앱 시작 로직...
});
```
버튼 없이 그냥 "첫 터치/클릭 아무거나"로 진입시키고 싶다면 `ClassroomGuard.fullscreen.enable()`을 옵션 없이 호출해도 됩니다 (기본값 `autoRequestOnFirstGesture: true`).
- 나가는 방법: 키보드 **ESC** (브라우저 표준 동작이라 항상 가능), 또는 **화면 왼쪽 위 구석을 1.5초 안에 3번 톡톡 누르기** (키보드가 없는 태블릿용 제스처, 옵션으로 위치/횟수 조절 가능).
- ⚠️ iOS Safari는 Fullscreen API 제약이 있어 아이패드/아이폰에서는 완전히 동작하지 않을 수 있습니다. Android 태블릿/Chrome/Windows에서는 정상 동작합니다.

**2) 손바닥 오탐 방지 (팜 리젝션 대체)** — 액정에 손바닥을 대고 그릴 때 생기는 오작동을 줄여줍니다. 웹 표준에는 "이건 손바닥이다"를 알려주는 공식 API가 없어서, 대신 "여러 포인터가 동시에 닿아도, 그 중 실제로 움직이기 시작한 첫 번째 포인터만 활성으로 인정하고 나머지는 그 포인터가 끝날 때까지 전부 무시"하는 방식으로 대체합니다.
```js
const tracker = ClassroomGuard.singlePointer.attach(canvas, {
  onStart(pos, evt) { /* 그리기 시작 (탭도 여기로 들어옴) */ },
  onMove(pos, evt)  { /* 그리는 중 */ },
  onEnd(pos, evt)   { /* 손을 뗌 */ }
});
```
이 프로젝트에서는 STEP 1(가이드 따라 그리기)과 STEP 2(채색의 펜 모드)에 이미 적용돼 있어요. 파일 상단 주석에 동작 규칙과 옵션이 자세히 설명되어 있습니다.
